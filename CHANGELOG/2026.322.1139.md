## Summary

The candy's own check at `charly.yml:214` asserts `/usr/bin/nvidia-ctk` exists. On CachyOS it never has, because two builds of the same upstream version are visible and pacman takes the higher-priority one.

Head `63a4520c8eb9cf90d4da44cdbaaa0cbb888df00f`. Diff, from `gh pr view 23 --json additions,deletions,changedFiles`:

```text
+23 -0 files=1
```

The change, without the comment block that carries the evidence inline:

```text
+            - run: install nvidia-ctk from the Arch extra repo
+              command: pacman -Sy --noconfirm extra/nvidia-container-toolkit
+              run_as: root
```

plus the `package:` key that an earlier revision of this branch deleted (see *How tested*, last paragraph) and the commentary explaining the repo collision.

**Why a plan step and not a `package:` entry.** `package:` cannot name a repo: charly renders the bare name into the Containerfile and pacman resolves it by repo priority. Measured:

```text
cachyos-extra-v3/nvidia-container-toolkit 1.20.1-1.1   <- higher priority, wins
extra/nvidia-container-toolkit            1.20.1-1
```

The `cachyos-extra-v3` build ships `nvidia-cdi-hook` and `nvidia-container-runtime*` but **no** `/usr/bin/nvidia-ctk`; Arch's build does. The plan step names the repo explicitly, which pacman honours.
