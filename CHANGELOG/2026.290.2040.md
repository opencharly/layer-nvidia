# 2026.290.2040 — fix(nvidia): let the gpgcheck probe skip on a dnf-less arm regardless of /etc/yum.repos.d

## Summary

**Head `8cb02a4`.** The prior revision was BLOCKed because the bed I had added carried a red `start` phase. This revision supplies the runtime proof on the correct instrument — the documented **pure-box** path — which has no deploy phase to fail, and the gate is green.

## The defect

`#12` removed the `stdout:` matcher so the Arch arm could skip honestly, and left the guard deciding whether to skip:

```
if [ ! -e /etc/dnf ] && [ ! -e /etc/yum.repos.d ]; then exit 0; fi
```

Skips only when **both** are absent, while the comment above states the intent as *"no DNF at all"*. Arch-family arms have no `/etc/dnf`, but `/etc/yum.repos.d` **does** exist there — this same file records why: `/etc/yum.repos.d/nvidia-container-toolkit.repo` still reads `gpgcheck=0` in the built image. So the guard was `true && false`, the arm fell through to the Fedora assertion, and exited 1 on a DNF repo it does not have. Fixed by testing for dnf **tooling**:

```
if ! command -v dnf >/dev/null 2>&1 && [ ! -e /etc/dnf ]; then exit 0; fi
```

## Why the bed is gone

The previous revision added `check-nvidia-probe` (a `pod:` bed). `check run` always deploys, and this repo's probe box has nothing long-lived to run, so the deploy phase crash-looped: *"Automatic restarting of a unit has been scheduled"* in the unit journal, `start` failing at ~1m31. **Four box compositions, identical failure** (`arch.arch`; `arch.vscode-test`; `arch.vscode-test` + `supervisord`, the init candy verified staged; `arch.check-tmux-box`), while `check-cachyos-ollama-pod` deploys fine on the same host. Filed as **`opencharly/plugin-deploy-pod#34`**.

So the bed shape this probe needed was a shape that always deploys — and the probe is a build-context check. It is removed, and the proof is the pure-box run above, which is the disposable build-context instrument the check framework documents for exactly this case.
