# 2026.326.0913 — feat(nvidia)!: delete the duplicate driver strip — a VM guest owns its driver (successor to #31)

## Summary

**Successor to #31**, which the validator auto-closed after its BLOCK rounds. Every round's fix
is in this head: the surviving gpgcheck rationale restored (and left exactly as `main` has it),
the `arch` import bumped so the project loads, the new check fixture-reproducible via
`CDI_KEEP_LIB_DIRS`, and the sweep pasted from the committed tree with its one documentation hit
explained. Supersedes #31.

Deletes `nvidia-drop-driver-userspace`, the **second copy** of layer-cuda's driver strip.
`opencharly/layer-cuda#34`.

It was added for POD images that composed `layer-nvidia` beside `layer-cdi`; measured on a cachyos
ollama pod, the image's `nvidia-utils` beat the CDI mount (`Failed to initialize NVML:
Driver/library version mismatch`). That composition no longer exists — pods base on `pod-cdi`, and
`layer-cdi` FAILS a build that bakes a driver user-space — so every remaining composer is a VM or an
appliance, where the **guest owns its driver**:

```
check-cachyos-gpu-vm, check-selkies-labwc-nvidia-vm, check-selkies-kde-nvidia-vm,
cachyos-gpu, charly-cachyos-app
```

Stripping there deletes the driver the guest needs, and this is the copy that can strip a **HOST**
(it composes on `nvidia-cdi-host` in this very manifest). `layer-nvidia` becomes install-only: the
toolkit, the Vulkan ICD assets, `LD_LIBRARY_PATH`, the ICD directory. The strip, its rationalising
comment block and its survival assertion go with the step; the description says what the layer is
now.

A new control makes a re-added strip fail: **`nvidia-keeps-distro-driver`** (build context, in the `nvidia` candy so EVERY composition runs it) asserts
the Arch arm's package-provided driver user-space is PRESENT; the Fedora arm packages none (libva
only) and says so.

Two incidental defects the change surfaced, fixed here:

- the removal range had swallowed the SURVIVING `nvidia-container-toolkit-gpgcheck-enforced` check's
  14-line rationale block; it is restored verbatim, and that check — including its `f=` lookup
  and the file name it names — is left exactly as `main` has it (`git fetch origin main; git
  show FETCH_HEAD:charly.yml`). The check cannot land without the evidence it is built on;
- the `arch` import moves `v2026.290.1914` → `v2026.325.1112`: at the old tag the stricter loader
  refuses the project outright on a bed member (`arch.check-arch-vm`), so no command in this repo
  ran at all.
