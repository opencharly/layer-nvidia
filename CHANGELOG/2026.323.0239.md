# 2026.323.0239 — fix(nvidia): anchor the driver-user-space glob so the strip keeps the CUDA runtime

## Summary

`nvidia-drop-driver-userspace` deleted with the PREFIX glob `-name 'libcuda*.so*'`. That prefix
family is not the driver's alone: it also contains the CUDA RUNTIME — `libcudart.so`,
`libcudart.so.13`, `libcudart.so.13.5.37`, `libcudart_static.a`, `libcudadevrt.a` — so the step
deleted what `layer-cuda` had just stitched. It is live in a pod composition: `layer-nvidia` is
built as a SEPARATE image on top of the box, AFTER `layer-cuda`'s stitch, and the measured image
had `/opt/cuda/lib64/libcudart.so*` present while `/usr/lib/libcudart.so*` was gone, so
`layer-cuda`'s own cudart check exited 2 (opencharly/layer-nvidia#25, bed `check-comfyui-pod` run
`2026.323.0203`).

Three files carry the change:

- `charly.yml` — the strip step is anchored, guarded, layout-scoped and defined once; the candy
  `description:` no longer claims the image ships driver libs.
- `.agents/skills/nvidia-layer/SKILL.md` — the strip section documents the anchor, the drift
  control, the keep-guard and the layout scope; its frontmatter stops claiming "driver libs".
- `.agents/skills/nvidia/SKILL.md` — the box-facing skill's three "driver libs" claims are
  corrected the same way.

leaves the two `nvidia-ctk` assertions untouched, because a pod image must not carry the binary.
