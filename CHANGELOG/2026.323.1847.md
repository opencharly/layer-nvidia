# 2026.323.1847 — docs: the check runner DOES honour exclude_distro; correct the rulebook and the step

## Summary

Two live surfaces in this repo told the reader that a step-level `exclude_distro:`
is inert — `AGENTS.md` and the `nvidia-container-toolkit-gpgcheck-enforced` step
comment ("the check runner does not honour runner-level exclude-distro fields").
The code says the opposite, so **the prose is the stale side**:

- `sdk/kit/planrun.go:181-189` — `RunOne` returns `StatusSkip` when any of the
  image's distro tags intersects `c.ExcludeDistros`, before any verb dispatch;
- `sdk/kit/planrun_test.go:97` — `TestRunOne_ExcludeDistros` pins that skip;
- `plugin-check`'s `candy/plugin-check/run_box.go:61,68` and
  `candy/plugin-check/live_gather.go:220,227` — both gathers seed
  `CheckEnv.Distros` from `meta.Distro`, so the list is not empty when a baked
  plan's check runs;
- `spec/schema/00_common.cue:217-221` — documents it as a SHARED step-level filter
  read by the generic `runOne` for every verb, "NOT a package-exclusive field".

The schema and the runner agree with each other and with the tests; no fix is
applied to either. What was wrong is the rulebook sentence, and the step comment
copied from it. Both now state the verified semantics.

**The in-command guard stays, for a reason the correction leaves standing.** The
guard decides on the TOOL ("is there DNF to assert against?"), not on a distro
NAME: a tag list would have to enumerate every DNF-less derivative by hand (arch,
cachyos, omarchy, …), and a new one would silently run a Fedora assertion it
cannot satisfy. The field filters distro tags; it cannot express that. It is also
a CHECK-runner filter: the BUILD emitter never reads it, so a `run:` install
step's `exclude_distro:` is inert at image-build time — now said explicitly rather
than conflated with the check runner.

The same sentence is copied into `opencharly/layer-cuda`'s `AGENTS.md` and its
`cuda-arch-header-root` step; that twin is swept in its own PR (claim-keyed sweep,
R5), because it is another repo's rulebook.
